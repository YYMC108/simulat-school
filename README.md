# 🎓 大学生活模拟器 (campus-life)

一个**数据驱动**的文字养成游戏。你是一名计算机专业大三学生，一个学期 16 周，
每周 3 点行动力，在「学业 / 社交 / 健康 / 心情 / 金钱 / 技能」之间做取舍，
最后走向 10 种不同结局之一。

## 快速开始

```bash
pnpm install              # 装依赖
pnpm dev:web              # ★ Web 界面（开发服务器，带热更新）→ http://localhost:5173
pnpm build:web            # 构建 Web 产物到 dist/
pnpm preview:web          # 预览构建产物
pnpm play                 # 命令行试玩
pnpm play -- --seed 2025  # 复现某一局（开局会打印随机种子）
pnpm test                 # 跑单元测试（33 个，含界面渲染）
pnpm typecheck            # 类型检查
pnpm simulate             # 数值平衡模拟：6 种决策风格 × 200 局
pnpm simulate -- --games 1000   # 加大样本量
pnpm preflight            # 推送前自检：代码健康 + 架构边界 + GitHub 连通性
```

> **Web 界面**：`pnpm dev:web` 后打开 http://localhost:5173 。
> 手机连同一个 WiFi 也能访问（开发服务器监听局域网，终端会打印地址）。
> 支持 `?seed=2025` 复现某一局，链接可以直接分享。

> **颜色说明**：结算回执默认只在确认支持 ANSI 的终端里上色（Windows Terminal / VS Code 终端 / ConEmu），
> 因为 PowerShell 5.1 的旧版控制台会把转义序列显示成乱码。想强制开启：`$env:FORCE_COLOR=1; pnpm play`。

## 架构：为什么这样分层

```
src/
  engine/          ← 引擎层：纯 TypeScript，零浏览器依赖
    types.ts         所有核心类型（状态 / 条件 / 效果 / 内容定义）
    rng.ts           可复现的伪随机数发生器
    conditions.ts    条件 DSL 的求值
    effects.ts       效果的应用
    state.ts         状态创建 / 日志 / 深拷贝
    engine.ts        流程编排（GameEngine 类）
  data/            ← 内容层：全是数据，不含逻辑
    config.ts        数值配置（含每周衰减）
    actions.ts       每周可选行动
    events.ts        事件库  ← 加内容只需要改这个文件
    endings.ts       结局表
  cli/             ← 界面层 A：命令行
    play.ts          交互式试玩
    simulate.ts      数值平衡模拟器
    text.ts          终端排版（CJK 宽度 / 颜色能力检测）
  web/             ← 界面层 B：浏览器（React）
    useEngine.ts     引擎适配层（唯一认识引擎的地方）
    App.tsx          页面骨架
    styles.css       样式
    components/      属性面板 / 日志流 / 行动面板 / 事件卡 / 结算回执 / 结局页
tests/
  engine.test.ts    引擎与内容（27 个）
  web.test.tsx      界面渲染冒烟（6 个）
```

界面是**两个平行的层**，都只依赖 `data/` 和 `engine/`：

```
   cli/ ──┐
          ├──依赖──▶  data/  ──依赖──▶  engine/
   web/ ──┘                              ▲
                                         │
                        tests/ ──────────┘
```

**`engine/` 完全不认识这两个界面**。这不是一句口号：加 Web 界面时，
`src/engine/` 的改动是 **0 行逻辑**（只加了一个展示顺序常量，见下）。

`engine/` **不认识** `data/` 和 `cli/`；`data/` 也不认识 `cli/`。
内容通过构造函数注入给引擎（依赖注入），所以：

- 换一套内容（比如改成「职场生活模拟器」）不用改引擎一行代码
- 引擎可以脱离界面单独测试，33 个测试跑完只要 1 秒多
- 同一个引擎，命令行能驱动，以后 React 也能驱动

## 四个关键技术点

### 1. 用数据描述逻辑：条件 DSL + 效果 DSL

不写 `if (academic > 80 && week > 10)`，而是写成数据：

```ts
requires: {
  type: 'all',
  conditions: [
    { type: 'week', op: '>=', value: 10 },
    { type: 'stat', key: 'skill', op: '>=', value: 60 },
  ],
}
```

效果同理：

```ts
effects: [
  { type: 'stat', key: 'skill', delta: 6 },
  { type: 'setFlag', key: '拿到实习Offer', value: true },
  { type: 'if', requires: { type: 'chance', probability: 0.3 }, effects: [...] },
  { type: 'branch', options: [{ weight: 6, effects: [...] }, { weight: 4, effects: [...] }] },
]
```

好处：**策划改数值不用碰代码**，TS 的类型还能在编译期抓住写错的字段名。

### 2. 注入随机数种子 → 整局游戏可复现

```ts
const engine = new GameEngine(GAME_DATA, { seed: 42 })
```

同一 seed + 同一串决策 = 同一结局。这让单元测试可以断言随机行为，
也让「存档回放」和「数值平衡模拟」成为可能。

### 3. 兜底分支：游戏永远不会卡死

结局表最后一条的 `requires` 是 `{ type: 'all', conditions: [] }`，
空 `all` 恒为真 → 任何情况下都能匹配到结局，并且有测试专门守着这条不变量。

### 4. 结算回执：玩家看到的数字必须是真的

每次行动、每个选择、每周结束都会显示**实际**的属性变化：

```
▸ 〔第1周〕你选择了「去图书馆自习」
    学业 +4       心情 −2       健康 −1
· 每周固定衰减
    学业 −1       技能 −1       社交 −1
    健康 −1       心情 −1       金钱 −¥100
```

关键在「实际」两个字 —— 学业 98 时选自习，菜单预告说 `+4`，但回执显示 `+2（已满）`。
如果回执照抄预告让玩家高兴，他会一直做无效投入，**永远学不会该换方向了**。

预告和回执**故意用两套逻辑**（声明值 vs 实际值），因为一旦有属性上限、`if` 条件、
`branch` 概率分支，两者必然分叉。有一条不变量守着它：

> **报告的变化量之和，必须等于属性的真实变化。**

它不关心引擎内部怎么算，只要求「你说变了多少」和「实际变了多少」永远一致 ——
这让我们能立刻区分「引擎算错了」和「显示/文案有歧义」，不会去乱改本来正确的代码。

## 数值平衡：模拟器发现了什么

这是这个项目里最有价值的经验。**光靠人肉试玩，你永远发现不了下面这些问题。**

`pnpm simulate` 会用 6 种决策风格各跑几百局，输出结局 × 风格的命中率矩阵。
迭代过程中它抓出了三类问题：

### 问题一：数值全面溢出

第一版每个行动给 +6~+8。48 次行动对 0–100 的刻度来说是碾压，
结果平均学业 95、社交 99、技能 94，保研率 36%。

**修法**：引入**每周衰减**（学业/技能/社交/健康各 −1，心情 −2）。
不持续投入就会退步，行动力立刻变成稀缺资源。同时把所有正向收益压到 +4 左右。

### 问题二：结局互相「饿死」

`学业崩塌` 的触发条件是 `academic < 25 || mood < 10`，
而 `情绪崩溃` 是 `mood < 25 && social < 35`。

结局是**按优先级取第一个满足的**，所以 `学业崩塌` 把 mood 那条线抢走了，
`情绪崩溃` 在 3000 局里一次都没触发过 —— 一段死代码。

**修法**：**一个坏结局只对应一个核心失败维度**。学业归学业（`academic < 25`），
身体归身体（`health < 15`），心情归心情（`mood < 15`），三条线互不重叠。

### 问题三：坏结局把好结局堵死

心情每周 −2，加上学习/写代码/兼职每次 −2，导致「学霸」风格 47% 情绪崩溃、
「技术宅」63% 情绪崩溃。而坏结局优先级更高，意味着**一旦心情崩了，
所有好结局都不可能达成**，`技术宅的胜利` 常年 0%。

**修法**：心情衰减减半到 −1，崩溃阈值下调到真正的灾难级别（< 15）。
另外发现 `投简历` 白送社交 +2，让「孤僻的技术宅」这个设定根本走不通，也去掉了。

## 已知的坑（踩过并已修）

1. **`not chance` 不是 `chance` 的反面** —— 那是两次独立随机，可能两个分支都不中。
   概率分支必须用 `branch`（按权重必定命中一个）。
2. **readline 在没有监听 `line` 事件时会丢掉已缓冲的行** ——
   重定向输入时只有当前 `question()` 挂着的那一行能被接住。
   改用 `rl[Symbol.asyncIterator]()`（内部有行队列）。
3. **`question()` 在输入流 EOF 时 promise 永不 settle** ——
   进程会卡在 top-level await（退出码 13）。异步迭代器会给出 `done`。
4. **行动文案不要手写数值** —— 改了 `effects` 却忘了改描述就会不同步。
   改用 `describeEffects(action.effects)` 自动生成。
5. **npm script 名会被包管理器内置命令遮蔽** —— 我最初把自检脚本命名为
   `pnpm doctor`，结果跑的是 **pnpm 自己的 `doctor`**，不是我的脚本。
   必须 `pnpm run doctor` 才能跑到脚本，所以改名叫 `preflight`。
6. **`.ps1` 脚本里有中文就必须存成带 BOM 的 UTF-8** ——
   Windows PowerShell 5.1 读取无 BOM 的 UTF-8 脚本会按 GBK 解码，
   所有中文变乱码。而 `.npmrc` / `.gitignore` 这类**配置文件反过来要保持纯 ASCII**，
   因为它们的读取方不一定按 UTF-8 解码。规则是：**脚本可以带 BOM，配置必须纯 ASCII。**
7. **临时文件要在 `git add` 之前就忽略掉** —— 我用 `.tmp-commit-msg.txt` 写长提交信息，
   先 `git add -A` 才删除它，结果它被提交并推到了公网仓库，只能再补一个清理 commit。
   现在 `.gitignore` 里有 `.tmp-*` 和 `*.tmp`。
8. **⚠️ Windows PowerShell 5.1 下不要用 `Get-Content` / `Set-Content` 往返处理 UTF-8 文件**
   —— 这是本项目踩过最严重的一个坑，会造成**静默数据损坏**：

   ```powershell
   # 危险！这两行合起来会毁掉文件
   (Get-Content package.json -Raw) -replace 'a','b' | Set-Content package.json -Encoding UTF8
   ```

   - `Get-Content` 在 PS 5.1 里**默认按系统 ANSI 码页读取**（简中 Windows 上是 GBK），
     所以 UTF-8 的中文被误解码成乱码字符
   - `Set-Content -Encoding UTF8` 又把这些乱码字符以 UTF-8 写回，**损坏不可逆**
   - 而且 `-Encoding UTF8` 会**额外写入 BOM**，导致 `JSON.parse` 直接抛
     `Unexpected token ''`，`pnpm` 也读不了 `package.json`

   这个坑当时真的把 `package.json` 推到了 GitHub 上，只能从上一个完好提交恢复。

   **正确做法（二选一）**：
   ```powershell
   # A. 需要精确控制字节/BOM 时，用 .NET（$false = 不写 BOM）
   $t = [System.IO.File]::ReadAllText($p, [System.Text.Encoding]::UTF8)
   [System.IO.File]::WriteAllText($p, $t, (New-Object System.Text.UTF8Encoding $false))

   # B. 只改文本内容时，直接用编辑器（本项目里就是 edit 工具），别让 shell 参与
   ```

   **BOM 规则一句话总结**：`.ps1` 脚本里有中文就**必须带 BOM**（否则 PS 5.1 按 GBK 读成乱码）；
   `.json` / `.npmrc` / `.gitignore` 这类**配置文件必须无 BOM 且纯 ASCII**。
   本仓库可以随时用这条命令自检：
   ```powershell
   Get-ChildItem -Recurse -File | Where-Object { $_.FullName -notmatch 'node_modules|\\\.git\\' } | ForEach-Object {
     $b = [System.IO.File]::ReadAllBytes($_.FullName)
     if ($b.Length -ge 3 -and $b[0] -eq 0xEF -and $b[1] -eq 0xBB -and $b[2] -eq 0xBF) { $_.Name }
   }
   ```
   正常输出应该**只有 `preflight.ps1`**。
